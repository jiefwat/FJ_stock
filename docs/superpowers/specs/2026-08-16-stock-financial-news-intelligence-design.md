# 个股财报与新闻舆情设计

日期：2026-08-16

## 目标

个股结论同时覆盖价格、资金、结构化财务和近期新闻风险。所有结论必须可复核、可降级；缺少财报或新闻时明确标记缺口，不用行情指标代替基本面。

## 方案选择

采用“结构化数据 + 保守入模”。不采用纯元数据展示，因为它无法回答盈利和现金流质量；不采用大模型联网自由检索作为主链路，因为结果难以复现且生产环境未启用联网搜索。

## 数据边界

- 财务数据：通过 `backend/src/marketdesk/providers/` 请求东方财富结构化主要财务指标，读取最近五个报告期。
- 新闻数据：通过 provider 请求东方财富个股新闻搜索，保留标题、摘要、媒体、链接和发布时间。
- 公告、研报和题材仍使用现有证据接口；不把研报评级直接当成买入依据。
- 浏览器只访问 `/api/v1/*`，不直接访问任何外部数据源。

## 财务分析

标准化字段包括营收、营收同比、归母净利润、净利润同比、ROE、毛利率、每股经营现金流、经营现金收入比和资产负债率。分析规则：

1. 至少一个有效报告期才生成财务结论。
2. 同比增长、ROE、现金流和负债分别评分；行业不适用字段保持缺失，不按零处理。
3. 利润下滑、现金流背离和高负债形成风险标记。
4. 财务影响单独显示，最多为个股确定性评分增加 6 分或扣除 10 分。
5. 缺失财务数据不扣分，只降低证据覆盖度并显示“财报待补”。

## 新闻舆情

新闻使用确定性关键词分为正向、负向和中性，并按发布时间衰减。规则：

1. 正向新闻只展示，不提高买入评分。
2. 只有包含立案、处罚、退市、预亏、利润大幅下降、违约等硬风险词的近期负面新闻，才形成最多 6 分的风险扣分。
3. 普通评论、行业讨论和标题情绪不触发交易决定。
4. 页面展示近 30 天情绪分布、硬风险数量和最近三条高相关报道。
5. 数据源失败时保留行情与财务结论，并单独标记新闻不可用。

## 服务与契约

- 新增严格模型：`FinancialPeriod`、`FinancialHealth`、`StockNewsItem`、`StockNewsSentiment`。
- provider 新增 `fetch_financial_periods` 和 `fetch_stock_news`。
- `MarketService.stock()` 并发获取 K 线、语义研究、财务和新闻，失败按能力隔离。
- `analyse_stock()` 接收标准化财务与新闻，输出独立分析块并把可解释影响加入已有证据账本。
- `StockDossier` 返回财务健康和新闻舆情；问股继续复用同一个 dossier。

## 界面

个股核心决定后增加两张紧凑卡：

- 财务健康：结论、报告期、营收同比、利润同比、ROE、现金流和负债率。
- 新闻舆情：30 天倾向、硬风险数量、最近报道及来源链接。

卡片只使用“盈利承压”“现金流背离”“负面风险 1 条”等结论型短语，不增加解释性旁白。详细报告期和新闻列表放在折叠区，390px 不产生横向滚动。

## 错误与降级

- 单一外部源失败不阻断个股行情和技术分析。
- 无财报、无新闻、上游超时分别返回可见的 unavailable 状态。
- 不缓存原始 provider payload，只缓存标准化模型；不记录 API 密钥。
- 新闻链接只允许 `http` 或 `https`。

## 验收

- provider 归一化测试覆盖有效值、空值、重复报告期、JSONP 和异常响应。
- 分析测试覆盖健康财务、利润/现金流背离、高负债、普通负面评论和硬风险新闻。
- API 测试证明两个数据源失败可独立降级。
- 前端测试证明财务与舆情结论可见，详细内容按需展开。
- `make verify`、生产构建、390px 浏览器验收和公网健康检查通过。
